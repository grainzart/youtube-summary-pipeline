# YouTube Summary Pipeline

Автоматизация ручного конвейера промптов пользователя: подробное саммари → раунды дополнений упущенного (пока не сойдётся) → объединение в единый текст без потерь → полная стенограмма по главам. Работает по субтитрам, потому что у модели нет доступа к самому видео.

Проект — этот репозиторий; все команды выполняются из его корня. ВСЁ (файлы, вывод, кэш) создаётся только внутри папки проекта, вне её ничего не писать.

## Шаг 0. Разбор запроса

- Извлеки из сообщения ссылку YouTube: `youtube.com/watch?v=...`, `youtu.be/...`, `youtube.com/shorts/...`. Мусорные параметры (`?t=`, `&list=`) чистить не нужно — yt-dlp разберётся сам.
- Несколько ссылок — обработай каждую отдельным прогоном конвейера (у каждой своя рабочая папка).
- По умолчанию запускается полный конвейер. Если пользователь явно просит «только саммари, без стенограммы» — пропусти субагента «стенограмма», секция стенограммы в финальный файл не попадёт.
- Не задавай уточняющих вопросов — пользователь ждёт готовый результат.

## Шаг 1. Субтитры и метаданные (Bash)

```bash
uv run fetch_subs.py "<URL>"
```

stdout — одна строка JSON: `work` (рабочая папка), `transcript`, `meta`, `lang`, `source` (`manual` | `auto` | `auto-translated`), `chars`, `title`, `author`, `duration_sec`. Рабочая папка: `work/<Автор>_<Название>_[<video_id>]` — без пробелов (подчёркивания, удобно в терминале), автор в начале, чтобы `work/` сортировалась по каналам. Скрипт сам определяет язык оригинала видео (по метаданным и оригинальной автораскадровке — у видео с дубляжами берётся именно оригинал, а не перевод) и качает субтитры на этом языке: ручные, иначе оригинальная автораскадровка; если оригинал не ru/en — автоперевод (ru, затем en).

- Код возврата не 0 → покажи пользователю текст ошибки и остановись.
- `chars` < 1500 → субтитры почти пустые (музыка, очень короткое видео): предупреди пользователя в финальном отчёте, но продолжай.

## Шаг 2. Конвейер субагентов

Дальше этапы через Agent tool (subagent_type: `general-purpose`). W — путь рабочей папки из JSON шага 1 (в bash используй прямые слэши). Каждый субагент читает нужные файлы сам (Read) и результат пишет через Write — большие тексты в ответе не дублируются, только короткий отчёт.

Если `chars` > 50000 (видео длиннее ~40 минут) — сразу предупреди пользователя, что полный конвейер займёт до часа: каждый субагент обрабатывает сотни тысяч символов и может работать 5–30 минут. Это НЕ зависание — не перезапускай субагентов, дождись ответа. После завершения каждого этапа пиши пользователю однострочный статус («стенограмма готова: 12 глав», «дополнения, раунд 1: +4 раздела»).

Порядок запуска:

1. ОДНОВРЕМЕННО два Agent calls в одном сообщении: «саммари-v1» и «стенограмма» (они независимы).
2. Когда «саммари-v1» готов → запусти «additions-1».
3. Если additions-1 создал содержательный 02_additions.md → запусти «additions-2». Файл не создан = агент сразу ответил «нечего добавить» → переходи к merge.
4. Если additions-2 создал файл и ответил «СТАТУС: много» → запусти «additions-3» (жёсткий потолок — 3 раунда дополнений).
5. Сделай `ls "{W}"`, выпиши реально существующие файлы 0N_additions.md и подставь этот список в промпт merge. Запусти «merge».

Сигнал сходимости — статус в ответе последнего раунда дополнений: как только раунд ответил «СТАТУС: ничего» (файл при этом не создаётся), важные пропуски закончились. Раунды повторяются, пока находятся пропуски, а не фиксированное число раз.

### Общий блок правил (вставляй в промпт каждого субагента дословно)

```
ПРАВИЛА ФОРМАТИРОВАНИЯ (обязательны):
- Пиши на русском языке.
- Подзаголовки уровня ### в формате: ### <эмодзи> <Заголовок>.
- Эмодзи ставь ТОЛЬКО в подзаголовках, по одному на подзаголовок.
- Текст следующего абзаца идёт СРАЗУ после строки подзаголовка, без пустой строки между подзаголовком и текстом.
- Не используй линии --- и лишние пустые строки между разделами внутри текста.
- Важные цифры, имена и термины выделяй жирным. Хайлайты (==...==) НЕ используй нигде — они зарезервированы для ручного выделения человеком при чтении конспекта.
- Не выдумывай факты, которых нет в субтитрах; имена, числа и термины передавай точно.
```

### Субагент 1 «саммари-v1» → W/01_summary.md

```
Прочитай файл {W}/transcript.txt (инструментом Read; если он длиннее 2000 строк — читай частями до самого конца, обработай весь).

Сделай подробное саммари видео на русском языке, с описанием каждого пункта, и не просто перечисление тезисов, а с раскрытием сути. Формат — markdown с подзаголовками. Добавь эмодзи только для подзаголовков.

{ОБЩИЙ БЛОК ПРАВИЛ}

Сохрани результат в {W}/01_summary.md через Write. Заголовок «## Саммари» не добавляй — только содержимое с ### подзаголовками. В ответе укажи 1–2 предложения: о чём видео и сколько разделов. Полный текст в ответ не дублируй.
```

### Субагент 2 «additions-1» → W/02_additions.md (запускать всегда после саммари-v1)

```
Прочитай {W}/transcript.txt и {W}/01_summary.md.

Добавь важные тезисы и детали, которые упущены в этом саммари, чтобы дополнить его ниже, не меняя текст самого саммари. Оформляй как продолжение саммари: подзаголовки ### с эмодзи, с раскрытием сути каждого пункта.

{ОБЩИЙ БЛОК ПРАВИЛ}

Первой строкой файла выведи «СТАТУС: много» или «СТАТУС: мало» — насколько много важного ещё упущено в саммари, затем сами дополнения. Сохрани всё в {W}/02_additions.md. Если важного ничего не осталось — файл НЕ создавай вовсе, просто ответь «СТАТУС: ничего». В ответе — только статус и число добавленных пунктов.
```

### Субагент 3 «additions-2» → W/03_additions.md (если 02_additions.md содержательный)

```
Прочитай {W}/transcript.txt, {W}/01_summary.md и {W}/02_additions.md.

Добавь важные тезисы и детали, которые всё ещё упущены после предыдущих дополнений, не меняя уже написанный текст. Осталось ли ещё что-то важное? Если да — выпиши это с раскрытием сути.

{ОБЩИЙ БЛОК ПРАВИЛ}

Первой строкой файла выведи «СТАТУС: много» или «СТАТУС: мало», затем дополнения. Сохрани всё в {W}/03_additions.md. Если важного не осталось — файл НЕ создавай, просто ответь «СТАТУС: ничего». В ответе — только статус и число добавленных пунктов.
```

### Субагент 4 «additions-3» → W/04_additions.md (только если после additions-2 статус «много» и есть новые разделы)

Промпт как у additions-2, но читает ещё и 03_additions.md, пишет в {W}/04_additions.md. Это последний раунд — потолок равен трём.

### Субагент 5 «стенограмма» → W/стенограмма.md (запускать параллельно с «саммари-v1»)

```
Прочитай файл {W}/transcript.txt полностью (частями, если длинный).

Сделай полную стенограмму, с подписями кто и что говорит, НА ЯЗЫКЕ СУБТИТРОВ: видео на английском — стенограмма на английском, на русском — на русском. Язык возьми из поля lang из шага 1 ({LANG}); это язык файла transcript.txt, и подзаголовки делай на нём же. Это единственное исключение из правила «пиши на русском».

Раздели весь разговор на блоки/главы и сделай для каждого блока подзаголовок ### с эмодзи (краткое содержательное название главы).

- Если это диалог/интервью: реплики в формате «**Имя:** текст», между репликами пустая строка. Говорящих определяй по контексту (представления, обращения друг к другу, смена темы; маркеры >> в субтитрах означают смену говорящего). Если имена неизвестны — «Спикер 1», «Спикер 2».
- Если монолог (лекция, разбор): связный полный текст, разбитый на главы.
- Ничего не сокращай — передавай всё содержимое. Пропускать можно только слова-паразиты, междометия и технические пометки вроде [clears throat].

{ОБЩИЙ БЛОК ПРАВИЛ}

Сохрани в {W}/стенограмма.md через Write. Заголовок «## Стенограмма» не добавляй. В ответе — только число глав и число спикеров.
```

### Субагент 6 «merge» → W/summary.md

```
Прочитай {W}/01_summary.md и файлы дополнений из этого списка (только реально существующие, несуществующих файлов не касайся): {СПИСОК ФАЙЛОВ ДОПОЛНЕНИЙ ИЗ ls}.

Сформируй подробный единый текст (markdown, с подзаголовками и эмодзи) из всего, что выписано в этих файлах. В объединённом тексте ничего не удаляй и не сокращай. Просто объедини в один текст, но объедини умно, так, чтобы не было повторений тезисов — при этом каждая важная деталь из каждого файла должна остаться.

{ОБЩИЙ БЛОК ПРАВИЛ}

Сохрани в {W}/summary.md. Заголовок «## Саммари» не добавляй. В ответе — 2–3 предложения об итоговой структуре, ничего больше.
```

## Шаг 3. Сборка конспекта (Bash)

Запускай сборку только после того, как «merge» подтвердил в своём ответе, что summary.md сохранён, — иначе сборка упадёт с ошибкой «файл не найден».

```bash
uv run assemble_md.py --work "<W>"
```

stdout JSON: `out` — путь к готовому файлу (по умолчанию `summaries/<Автор>. <Название>.md` внутри проекта, с пробелами — для Obsidian). Структура по TEMPLATE.md: vid-блок → `## Саммари` → `## Мои заметки` (пустой раздел-заготовка для пользователя) → `## Стенограмма`, секции разделены `---`. Если пользователь просил конкретное место — добавь `--out "<полный путь>.md"`.

## Шаг 4. Отчёт пользователю

- Markdown-ссылка на готовый файл (абсолютный путь).
- Короткая статистика: язык и тип субтитров, длительность видео, сколько раундов дополнений прошло до сходимости, число глав стенограммы.
- Предложение: «Задавай вопросы по видео — отвечу по стенограмме, и по желанию коротко добавлю ответ в „Мои заметки"».

## Шаг 5. Вопросы по видео после конспекта

Когда пользователь (в этом же разговоре, после готового конспекта) задаёт вопрос по видео:

1. Ответь развёрнуто. Если ответа нет в контексте — прочитай W/transcript.txt или W/стенограмма.md из рабочей папки этого видео (путь был в шаге 1; если потерялся — найди папку в `work/` по названию видео через ls).
2. Затем через AskUserQuestion спроси: «Добавить краткую версию этого ответа в конспект (раздел „Мои заметки")?» с вариантами «Да, коротко записать» / «Нет, только ответ в чате».
3. При «да» вставь через Edit в готовый md короткую заметку в КОНЕЦ раздела «## Мои заметки»:
   - раздел ещё пуст — сразу после строки `## Мои заметки`;
   - в разделе уже есть заметки — сразу перед разделителем `---`, за которым идёт `## Стенограмма`.
   Формат заметки (с пустой строкой до и после неё):
   ```
   **<краткий вопрос>**
   <сжатый ответ: 2–4 предложения, только суть; самое главное — жирным. Хайлайты не использовать.>
   ```
   Конспект не раздувай: одна заметка — максимум несколько предложений; полные рассуждения остаются в чате. Если раздела «Мои заметки» в файле нет (конспект собран старой версией) — вставь его перед `## Стенограмма` вместе с заметкой.

## Если что-то пошло не так

- Субагент надолго «замолчал» — на длинных видео это норма (см. шаг 2), не перезапускай его.
- Ошибка 429 / «too many requests» при скачивании субтитров — лимит YouTube по IP: подожди 1–2 минуты и повтори шаг 1 РОВНО один раз. Не запускай попытки подряд и не зацикливай — каждая попытка продлевает блокировку. Если не помогло — вернись к пользователю и расскажи.
- Ошибка yt-dlp «Sign in to confirm you're not a bot» или про возрастное ограничение → видео требует авторизации YouTube, без cookies не обработать: сообщи пользователю и остановись.
- YouTube поменял разметку и yt-dlp устарел → `uv lock --upgrade-package yt-dlp && uv sync`, затем повтори шаг 1.
- Субагент вернулся без файла → перезапусти этого субагента один раз; если снова пусто — выполни его этап сам в основном контексте, прочитав нужные файлы.
